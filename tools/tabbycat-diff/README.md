# Differential testing against Tabbycat

This harness runs the same tournaments through the official [Tabbycat](https://github.com/TabbycatDebate/tabbycat)
and through CrabbyTab's own libraries, then compares the results by rule. It replaces "we believe
this matches Tabbycat" with recorded Tabbycat output. The latest findings are in
[`report/REPORT.md`](report/REPORT.md).

```
tools/tabbycat-diff/
  fixtures/generate.ts        seeded fixture generator (no app imports)
  fixtures/<name>/            tournament.xml (DebateXML) + config.json (what DebateXML cannot carry)
  tabbycat/                   the Tabbycat side: run_tabbycat.py, Dockerfile, docker-compose.yml, run-native.sh
  golden/<name>.tabbycat.json Tabbycat's output, committed so CI needs no Docker
  harness/                    CrabbyTab runner, rule-based comparison, report writer
  known-differences.json      the human verdict for every discrepancy
  report/                     REPORT.md and report.json, regenerated by the test
  tabbycatDiff.test.ts        the Vitest entry point (runs in `npm test`)
```

## What runs in CI

`npx vitest run tools/tabbycat-diff` (part of `npm test`) needs no Docker or Python. For every
fixture it:

1. imports `tournament.xml` with CrabbyTab's DebateXML importer;
2. applies Tabbycat's effective preferences, read from the golden file and translated by
   `translatePreferences` in `harness/crabbytab.ts`;
3. computes standings after every round, a draw for every round from the history before it (eight
   seeds), the break for every category and an adjudicator allocation, all through the real libraries
   (`calculateStandings`, `generateRoundDraw`, `calculateBreaks`, `computeAutoAllocation`);
4. compares the result with the golden file and classifies every discrepancy.

The test fails when a discrepancy has no verdict in `known-differences.json`, or when the set of
discrepancies or their verdicts differs from the committed `report/report.json`, for example when a
change fixes a known defect or introduces a new one. After reviewing the change, regenerate the report:

```bash
TABBYCAT_DIFF_WRITE=1 npx vitest run tools/tabbycat-diff
```

## How things are compared

Standings and breaks are deterministic under the same rules, so they are compared value by value.
Draws and allocations often have several valid answers, so they are compared by the properties the
rules constrain:

| Area | Compared | Notes |
|---|---|---|
| Standings | every team and speaker metric both engines compute (Tabbycat names), ranks, reply tab | tolerance 1e-4 relative; Tabbycat's `null` (no results yet) equals CrabbyTab's 0; Tabbycat metrics CrabbyTab lacks are listed |
| Draws | rooms, coverage (each available team exactly once), bracket composition, pull-ups, side imbalance, institution clashes and repeat pairings (when the rule is on), side-cap violations (two-team), Tabbycat's BP position cost, bye teams | judged on Tabbycat's standings from the previous round. A difference that also shows up between seeds of the same engine is auto-classified as a valid alternative. Properties no rule constrains, and identical rooms, are reported for information only |
| Breaks | breaking, reserve and different-break sets per category, highest priority first; break ranks of teams both engines break | CrabbyTab's cutoff ties (held out until the tab director resolves them) are shown next to Tabbycat's sets |
| Allocation | chairs present, personal, institution and adjudicator-adjudicator conflicts (hard), panel sizes, adjudicators used, adjudicator-team history repeats, sum of chair scores (10% band) | Tabbycat's voting allocator corresponds to CrabbyTab's `by_priority` sizing; its consensus allocator corresponds to `fixed` with every adjudicator spread over the panels |

Every discrepancy is classified as one of:

- **rule difference**: the engines implement different rules, and both are defensible;
- **CrabbyTab defect**: CrabbyTab is wrong or worse, and there is a follow-up;
- **configuration difference**: the setup could not be made identical;
- **valid alternative**: a different answer that satisfies the same rules.

## Fixtures

| Fixture | Covers |
|---|---|
| `bp-uneven` | BP, 26 teams (two byes a round, one in a round with an unavailable team), Open/ESL/EFL break categories with priorities, iron-person speeches, adjudicator conflicts |
| `australs-voting` | Australs two-team rules, unevenly sized institutions forcing swaps, 3-judge voting panels with split decisions, replies, an iron-person speech |
| `twoteam-odd-ties` | two-team with 19 teams (a bye every round), ranked on wins only (many ties, including at the break), fold with pull-up from top, at most three debates on one side |

The fixtures are generated, not hand-written. To change or add one, edit `FIXTURES` in
`fixtures/generate.ts`, then run:

```bash
node tools/tabbycat-diff/fixtures/generate.ts
```

The generator is deterministic: the same seed produces byte-identical files. Node prints a
`MODULE_TYPELESS_PACKAGE_JSON` warning because the repository has no `"type": "module"`; the warning
is harmless. After changing fixtures, regenerate the golden files (below), then the report.

The archived draws are only history: a simple points-then-speaks fold with byes for the lowest teams.
They are not meant to be good draws. Each engine draws round *n* from rounds 1 to *n*-1.

## Regenerating the golden files (Tabbycat side)

The golden files come from Tabbycat **v2.12.1** (commit `ce9488b5`). Both routes refuse to run if the
tag has moved. `run_tabbycat.py` imports each fixture with Tabbycat's own archive importer
(`importer.archive.Importer`), applies the configuration fixups below, and records standings
(`TeamStandingsGenerator`, `SpeakerStandingsGenerator`), draws (`DrawManager`, eight seeds per round),
breaks (`BreakGenerator`) and an allocation (`Voting`/`ConsensusHungarianAllocator`). Each fixture runs
in a transaction that is rolled back, so the database ends empty. Python's and PostgreSQL's RNGs are
seeded, so two runs produce byte-identical files.

With Docker:

```bash
docker compose -f tools/tabbycat-diff/tabbycat/docker-compose.yml run --rm --build tabbycat
docker compose -f tools/tabbycat-diff/tabbycat/docker-compose.yml down -v
```

Without Docker, you need Python 3.11, git and the PostgreSQL binaries (`initdb`, `pg_ctl`, `createdb`):

```bash
PG_BIN="/c/Program Files/PostgreSQL/18/bin" tools/tabbycat-diff/tabbycat/run-native.sh
```

The native script clones Tabbycat and installs its locked dependencies into
`~/.cache/crabbytab-tabbycat-diff` (override with `TABBYCAT_DIFF_WORK`). It also starts a throwaway
PostgreSQL cluster on `127.0.0.1:54329` with trust auth, and stops and deletes the cluster when it
exits. The first run takes about seven minutes (mostly `pip install`); later runs take a minute or
two. Downloaded code stays in its own directory; the harness only adds
`tabbycat/settings/local.py`, copied from `local_settings.py`. No credentials are involved: the
database uses trust auth and is reachable only locally or on the compose network.

### Configuration fixups

Tabbycat's archive importer leaves some fields at defaults. `apply_configuration` sets them from
`config.json`:

- preferences: the style preset (`bp`, `australs`) plus the fixture's `tabbycatPreferences`;
- break categories: size, reserve size, priority, general flag and rule (the importer sets size 0);
- round availability for every team and adjudicator, except the fixture's unavailable teams (the
  importer creates none);
- iron-person speeches: `SpeakerScore.ghost` and `TeamScore.has_ghost` for speeches marked
  `ghost="true"` (the importer ignores the attribute).

On the CrabbyTab side, the imported ballots are re-totalled with the translated rules. CrabbyTab's
importer totals them with its own defaults before any setting can be changed; the report lists this
as a configuration difference.

## Limitations

- One Tabbycat version (v2.12.1). Bumping it means updating the tag and commit in `Dockerfile`,
  `docker-compose.yml` and `run-native.sh`, then regenerating and reviewing the report.
- The Docker route is written but was not executed when this harness was built (Docker was not
  available). The native route produced the committed golden files.
- Debate importance is 0 on both sides (Tabbycat's importer does not set it), so the allocation
  comparison does not test importance-driven chair placement.
- Round 1 draws are random in both engines; only coverage, room count, byes and, where avoided,
  institution clashes are compared.
- Elimination rounds, feedback, motions and venues are not compared.
- Tabbycat behaviour that looks like an upstream bug is recorded as a rule difference with a note
  (see the report), not worked around.
